# 交易系统报告补充版

本版保留一对一、一对多与两组多对多实验，补齐报告示例中的技术功能。Java17、MyBatis3.5.19、MyBatis-Plus3.5.17、JUnit4.13.2；数据库连接从原项目common/db.properties读取。首次克隆时复制同目录db.properties.example为db.properties并填写本机连接；真实凭据不提交。

## IDEA入口

- 交易系统关联映射（一对一、一对多、两个多对多）：RelationRunner。
- 交易系统报告补充实验：TradeCompletionRunner。
- TradeRelationMapperTest（真实MySQL）：8项关联映射测试。
- TradeAdvancedFeaturesTest（真实MySQL）：8项报告补充测试。
- 中文控制台11：关联映射；12：报告补充。

构建全部应用：根目录运行build-apps.cmd。普通构建在隔离H2兼容模式下自动测试，真实MySQL测试通过JUnit运行配置的-Dtrade.real=true显式选择。

## 报告缺项与实现

| 技术点 | 代码与验证 |
|---|---|
| 商品乐观锁 | Product.@Version；OptimisticLockerInnerInterceptor；两个旧版本更新中第二次影响0行 |
| 自动填充 | Product.createTime/updateTime配合AuditClock；插入、更新自动填充 |
| Lambda查询与分页 | LambdaQueryWrapper，分类和最低价格筛选，第2页每页2条 |
| 动态条件 | ProductQuery；XML trim/if/foreach/choose；品牌IN、价格区间及条件排序 |
| 批量新增 | insertBatch通过foreach生成多组VALUES；测试数据回滚 |
| 选择性更新 | updateSelective通过trim/suffixOverrides生成SET，只修改传入字段 |
| 品牌关联 | lab_trade_brand与product.brand_id外键；association封装Brand对象 |
| 索引 | idx_trade_brand、idx_trade_product_name；元数据测试断言 |
| 品牌统计 | LEFT JOIN/GROUP BY/COALESCE，数量、总价、均价、最大及最小价格 |
| 二级缓存 | TradeMapper.xml的LRU缓存，60秒刷新，容量1024；Serializable实体及序列化副本 |
| 缓存命中 | 两个SqlSession相同查询，实际JDBC SELECT只执行1次 |
| 回滚不发布缓存 | 第一会话回滚，第二会话需重新执行SQL，共2次SELECT |
| 跨Mapper失效 | ProductPlusMapper用CacheNamespaceRef指向TradeMapper；共用工厂，MP提交修改后XML查回新库存 |

TradeDatabase负责建立共同的MybatisConfiguration与SqlSessionFactory，避免两个工厂缓存隔离。SQL日志沿用MyBatis StdOutImpl，可以看到Preparing/Parameters/Total及Cache Hit Ratio；TradeSqlCounter在JDBC prepare处计数验证真实SQL次数。

## 数据库同步与可重复运行

TradeSchema.upgrade对已有表执行增量升级：新增品牌表、商品brand_id/version/create_time/update_time列、品牌外键和两个索引。已有商品的brand文本保留，根据名称关联5个虚构品牌。已有客户、订单、明细及库存保留。

建库脚本：src/main/resources/database/trade-lab.sql。旧库升级逻辑：study/trade/TradeSchema.java。初始化使用幂等检查。该版不清空原数据库。

批量、乐观锁示例使用随机负数临时编号并回滚；缓存提交失效示例需要真实提交一个临时商品，并在finally中删除，仅操作该随机临时编号。
